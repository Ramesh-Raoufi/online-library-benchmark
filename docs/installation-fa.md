# راهنمای نصب و استفاده

این پروژه سیستم مدیریت کتابخانه و ابزار اندازه‌گیری عملکرد MySQL و CockroachDB است. برای اجرای برنامه Node.js نسخهٔ ۲۴ یا بالاتر لازم است.

## اجرای ساده

در پوشهٔ پروژه اجرا کنید:

```bash
npm ci
cp .env.example .env
```

فایل `.env` را باز کنید و ایمیل، نام و رمز مدیر را وارد کنید. رمز باید حداقل ۱۰ کاراکتر باشد؛ پروژه رمز پیش‌فرض ندارد.

```ini
ADMIN_EMAIL=your-email@example.com
ADMIN_NAME=Ramesh Raoufi
ADMIN_PASSWORD=your-unique-password
```

سپس:

```bash
npm run setup
npm run seed
npm start
```

آدرس `http://localhost:3000` را باز کنید و وارد شوید. زبان رابط از دکمهٔ فارسی/English تغییر می‌کند. فرمان `seed` فقط چند کتاب نمونه اضافه می‌کند؛ نتایج پژوهش یا امانت جعلی تولید نمی‌کند.

## استفاده از سیستم

۱. در بخش «افراد و دسترسی‌ها» حساب عضو و کتابدار بسازید.

۲. در «فهرست کتاب‌ها» کتاب، کد، قفسه و تعداد نسخه‌ها را ثبت کنید.

۳. مدیر یا کتابدار از «ثبت امانت» کتاب، عضو و مدت را انتخاب می‌کند.

۴. برای تحویل کتاب، در «امانت و برگشت» دکمهٔ «برگشت» را بزنید.

۵. عضو می‌تواند کتاب درخواست کند؛ ثبت امانت همان کتاب برای همان عضو، درخواست را انجام می‌دهد.

۶. در «گزارش‌ها» استفاده از کتاب‌ها و خروجی CSV را ببینید.

## اتصال دیتابیس‌های پژوهش

حالت پیش‌فرض SQLite برای اجرای محلی است و در مقایسهٔ MySQL و CockroachDB استفاده نمی‌شود. برای آزمایش واقعی، Docker و Compose را روی سیستم خود نصب کنید و سپس:

```bash
docker compose up -d --wait mysql cockroach
docker compose run --rm cockroach-init
npm run benchmark
```

تنظیمات اتصال در `.env.example` موجود است. اگر رمز MySQL را تغییر دادید، آدرس اتصال را نیز هماهنگ کنید. نام دیتابیس‌های آزمایش باید به `_benchmark` ختم شود. دیتابیس کتابخانه جدا است.

نتایج پس از اجرای موفق در پوشهٔ `results` ذخیره می‌شوند. مدیر می‌تواند از بخش «آزمایش دیتابیس» آزمایش را اجرا و JSON/CSV را دانلود کند. تا پیش از اجرای واقعی، هیچ عددی به‌عنوان نتیجه نمایش داده نمی‌شود.

نسخهٔ Docker برای آزمایش محلی تک‌نودی است؛ این آزمایش به‌تنهایی دربارهٔ توزیع‌شدگی، تحمل خرابی یا برتری عمومی یک دیتابیس نتیجه نمی‌دهد. جزئیات روش در `docs/benchmark-methodology.md` نوشته شده است.

## نکات عملی

- اطلاعات و رمزها را در `.env` نگه دارید؛ این فایل وارد گیت نمی‌شود.
- تغییر `DB_ENGINE` داده‌ها را بین دیتابیس‌ها انتقال نمی‌دهد؛ در دیتابیس جدید حساب مدیر را بسازید.
- همزمان فقط یک آزمایش روی همان دو دیتابیس اجرا کنید.
- برای اینترنت، HTTPS و دیتابیس با TLS لازم است؛ تنظیمات آزمایش محلی را به اینترنت باز نکنید.
- کتاب دارای سابقهٔ امانت یا درخواست حذف نمی‌شود تا گزارش‌ها باقی بمانند.
